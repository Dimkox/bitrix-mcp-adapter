# MCP-адаптер для 1С-Битрикс

Модуль `dimkox.mcp` даёт ИИ-агентам (Claude, Cursor, ChatGPT и любым другим MCP-клиентам) доступ к вашему сайту на Битриксе. Агент может найти товар в каталоге, прочитать новость, посмотреть заказ или подготовить описание товара, причём только в пределах прав того пользователя, от имени которого подключён.

Подключение идёт по открытому протоколу [Model Context Protocol](https://modelcontextprotocol.io). Идея та же, что у [WordPress MCP Adapter](https://github.com/WordPress/mcp-adapter): функции сайта описываются как «возможности» (abilities), а адаптер отдаёт их агенту как MCP-инструменты, ресурсы и промпты. Код написан с нуля под Битрикс и распространяется по лицензии MIT.

## Что умеет агент

| Возможность | Что делает | По умолчанию |
| --- | --- | --- |
| `main-current-user` | От чьего имени работает агент и какие у него группы | включена |
| `iblock-list-iblocks` | Список инфоблоков, доступных пользователю | включена |
| `iblock-list-sections` | Разделы инфоблока | включена |
| `iblock-search-elements` | Поиск элементов по названию и анонсу, с постраничной выдачей | включена |
| `iblock-get-element` | Элемент целиком: тексты и свойства | включена |
| `bitrix://site/info` (ресурс) | Сайты, домены, версия ядра | включена |
| `iblock-describe-element` (промпт) | Готовый запрос «напиши продающее описание» по данным элемента | выключена |
| `iblock-create-element` | Создать элемент (по умолчанию неактивным, чтобы человек проверил) | выключена, изменяет данные |
| `iblock-update-element` | Изменить поля и свойства элемента | выключена, изменяет данные |
| `main-search-users` | Поиск пользователей (персональные данные) | выключена |
| `sale-list-orders`, `sale-get-order` | Заказы интернет-магазина (персональные данные) | выключены |

Другие модули могут добавлять свои возможности, см. раздел [«Свои возможности»](#свои-возможности).

## Установка

1. Скопируйте папку `dimkox.mcp` в `/local/modules/` на сайте.
2. Откройте «Marketplace → Установленные решения» и установите «MCP-адаптер для ИИ-агентов».
3. В «Настройках модуля» на вкладке «Настройки» включите MCP-сервер. На вкладке «Возможности» отметьте, что разрешено агенту.
4. На вкладке «Токены» выдайте токен. Лучше завести для агента отдельного пользователя с нужными правами, а не выдавать токен администратору. Токен показывается один раз.

Требования: PHP 8.1+, модуль `main` из актуальных версий (используется D7 ORM). Модули `iblock` и `sale` не обязательны: их возможности появляются, только когда эти модули установлены.

## Подключение агента

Адрес сервера: `https://ваш-сайт.ru/bitrix/tools/dimkox.mcp/index.php`. Он же показан на странице настроек.

**Claude Code**

```bash
claude mcp add --transport http bitrix https://ваш-сайт.ru/bitrix/tools/dimkox.mcp/index.php \
  --header "Authorization: Bearer bxmcp_ВАШ_ТОКЕН"
```

**Cursor и другие клиенты с HTTP-транспортом** (`.cursor/mcp.json`):

```json
{
  "mcpServers": {
    "bitrix": {
      "url": "https://ваш-сайт.ru/bitrix/tools/dimkox.mcp/index.php",
      "headers": { "Authorization": "Bearer bxmcp_ВАШ_ТОКЕН" }
    }
  }
}
```

**Локально на сервере через STDIO** (например, Claude Desktop на той же машине):

```json
{
  "mcpServers": {
    "bitrix": {
      "command": "php",
      "args": ["/var/www/site/local/modules/dimkox.mcp/cli/stdio.php", "--root=/var/www/site"],
      "env": { "BITRIX_MCP_TOKEN": "bxmcp_ВАШ_ТОКЕН" }
    }
  }
}
```

## Безопасность

- **Всё выключено, пока администратор не включит.** Отключён сам сервер, а агенту видны только явно отмеченные возможности.
- **Права пользователя.** Токен действует от имени конкретного пользователя: чтение идёт через `CHECK_PERMISSIONS`, запись проверяется правами инфоблока (обычными или расширенными, с учётом раздела, в который создаётся элемент).
- **Черновики.** Неактивные и ещё не опубликованные элементы видны только при праве «просмотр в админке» (S) и выше, как в самом Битриксе.
- **Заказы** видны менеджеру только в тех статусах, которые ему разрешено просматривать в настройках доступа к статусам.
- **Ограничения записи.**
  - Агент может менять только свойства типов «строка», «число», «список», «привязка к элементу» и «привязка к разделу». Файловые свойства запрещены.
  - Инфоблоки с документооборотом или бизнес-процессами агент не меняет.
  - Указанные в настройках коды свойств (например, закупочная цена) агенту не видны вовсе.
- **Двойная защита записи.** Инструменты, изменяющие данные, работают, только если отмечены и сама возможность, и общий переключатель «Разрешить изменять данные».
- **Токены.** В базе хранится только SHA-256 хеш токена. Токен можно ограничить сроком и отозвать в любой момент.
- **Без cookies.** Каждый запрос авторизуется заголовком `Authorization: Bearer`, поэтому CSRF невозможен.
- **Origin.** Заголовок `Origin` браузерных клиентов проверяется по доменам из настроек сайтов и дополнительному списку. Заголовок `Host` запроса не учитывается, это защита от DNS rebinding. Для разрешённых доменов отдаются CORS-заголовки.
- **Журнал.** Каждый вызов пишется в журнал событий Битрикса (тип `DIMKOX_MCP_CALL`): кто, что, результат, время выполнения.
- **Внутренние ошибки не утекают.** Текст исключения остаётся в журнале, агенту приходит общее сообщение.
- Подключайте агентов только по HTTPS: токен передаётся в заголовке.

## Свои возможности

Любой модуль или `init.php` может добавить свою возможность через событие `OnMcpCollectAbilities`. Подробности и примеры: [docs/abilities.md](docs/abilities.md).

```php
use Bitrix\Main\EventManager;
use Dimkox\Mcp\Ability\Ability;

EventManager::getInstance()->addEventHandler('dimkox.mcp', 'OnMcpCollectAbilities', static function (\Bitrix\Main\Event $event): void {
    $event->getParameter('registry')->register(Ability::tool([
        'name' => 'shop-stock',
        'title' => 'Остаток товара',
        'description' => 'Возвращает остаток товара на складах по его ID.',
        'readOnly' => true,
        'inputSchema' => [
            'type' => 'object',
            'properties' => ['product_id' => ['type' => 'integer', 'minimum' => 1]],
            'required' => ['product_id'],
        ],
        'permission' => static fn (array $args): bool => $GLOBALS['USER']->IsAuthorized(),
        'execute' => static fn (array $args): array => ['quantity' => 42],
    ]));
});
```

После этого возможность появится на вкладке «Возможности», и её останется только отметить.

## Протокол

- **Транспорт.** Streamable HTTP без сессий: каждый `POST` несёт одно JSON-RPC сообщение, ответ приходит обычным `application/json`. Есть также STDIO.
- **Версии MCP:** `2025-11-25` и `2025-06-18`. Пакетные запросы (batch) отклоняются, как и требует спецификация с 2025-06-18.
- **Методы:** `initialize`, `ping`, `tools/list`, `tools/call`, `resources/list`, `resources/read`, `resources/templates/list`, `prompts/list`, `prompts/get`.
- **Ошибки.** Ошибки аргументов и выполнения инструмента возвращаются агенту как результат с `isError: true`, чтобы он мог исправиться. Ошибки протокола приходят как JSON-RPC ошибки.

## Разработка

```bash
php tests/run.php     # 42 теста, без зависимостей
composer lint         # php -l по всем файлам
```

- **`tests/McpServerTest.php`, `tests/HttpHandlerTest.php`, `tests/SchemaValidatorTest.php`:** протокол, транспорт и валидация.
- **`tests/BitrixWiringTest.php`:** связка с Битриксом на заглушках API (`tests/stubs/bitrix.php`): токены, права, инфоблоки, заказы, журнал. Заглушки проверяют код модуля, но не поведение настоящего Битрикса.
- **`tests/interop/`:** проверка официальным MCP-клиентом (Python SDK). Запуск:

  ```bash
  php -S 127.0.0.1:8765 tests/interop/demo-server.php &
  pip install mcp && python3 tests/interop/client.py http://127.0.0.1:8765/
  ```

## Ограничения

- **Не проверен на живом сайте.** Модуль проверен тестами и официальным MCP-клиентом, но ещё не на настоящем Битриксе: первая установка — на тестовой копии сайта.
- **Только статические токены.** OAuth-авторизация MCP не поддерживается, поэтому облачные коннекторы, которые умеют только OAuth, подключить не получится. Claude Code, Cursor и клиенты с заголовками работают.
- **Версия протокола по умолчанию.** Если клиент не прислал заголовок `MCP-Protocol-Version`, сервер считает версию `2025-11-25`, а не `2025-03-26`, как предлагает спецификация: 2025-03-26 не поддерживается.
- **Часовые пояса.** Если в Битриксе включены часовые пояса пользователей, даты старого API могут прийти со смещением пользователя.
